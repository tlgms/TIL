# redis `key *` 하면 안되는 이유

`Key *`는 모든 키를 조회하는 O(n)연산라서 싱글스레드인 Redis에선 큰 무리로 작용한다.

이로인해 문제가 발생할 수도 있습니다.

- Redis를 사용하는 웹 서버(Application)의 요청들이 타임아웃(Timeout)을 일으킵니다.

- 커넥션 풀(Connection Pool)이 가득 차서 웹 서버 전체가 마비됩니다.

- 최악의 경우, 트래픽을 감당하지 못한 데이터베이스(RDB)까지 함께 뻗어버릴 수 있습니다.

---

## **💡 해결책: 대신 ****`SCAN`**** 명령어를 사용하세요**

실제 운영 환경에서 특정 키들을 검색해야 할 때는 **`SCAN`**** 명령어**를 사용해야 합니다.

- **안전한 분할 조회:** `SCAN`은 한 번에 모든 데이터를 가져오지 않고, **커서(Cursor) 기반으로 데이터를 조금씩 나누어 반환**합니다.

- **서버가 멈추지 않음:** 한 번 요청할 때마다 아주 잠깐씩만 Redis를 점유하므로, 다른 클라이언트의 요청을 동시에 처리할 수 있어 서비스에 영향을 주지 않습니다.

**사용 예시 (와일드카드 검색):**

```bash
# 커서 0부터 시작해서 'user:'로 시작하는 키를 조금씩 안전하게 검색
SCAN0 MATCH user:* COUNT100
```

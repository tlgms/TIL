# 인덱스(Index)

### 1. 인덱스란?

- 데이터베이스 테이블의 검색 속도를 향상시키기 위해 사용하는 **색인(목차)** 구조.

- 모든 데이터를 처음부터 끝까지 찾는 **Full Table Scan**을 방지하고, 특정 데이터를 빠르게 찾는 **Index Range Scan**을 수행함.

### 2. 장점 & 단점


| **구분** | **주요 내용** |
|---|---|
| **장점** | • **SELECT 검색 속도 향상** (조회 성능 극대화) • `WHERE`, `JOIN`, `ORDER BY`, `GROUP BY` 조건 처리 시 효율적 |
| **단점** | • 추가 **저장 공간 필요** (보통 테이블 크기의 약 10%) • `INSERT`, `UPDATE`, `DELETE` 등 데이터 변경 시 **인덱스 재정렬 비용 발생** (성능 저하 원인) |

### 3. 주요 자료구조

- **B-Tree / B+Tree (가장 흔함)**
  - 자식 노드를 여러 개 가질 수 있는 균형 트리 구조.
  - $O(\log N)$의 검색 시간 복잡도를 가짐.
  - 데이터가 정렬 상태를 유지하므로 **부등호비교(****`>`****, ****`<`****) 및 범위 검색**에 매우 유용함.

- **Hash Table**
  - Key-Value 쌍으로 저장하여 $O(1)$의 압도적인 검색 속도를 제공.
  - 단, 동등 비교(`=`)만 가능하며 **범위 검색이 불가능**하여 DB 인덱스로는 제한적 사용.

### 4. 인덱스 종류

1. **클러스터드 인덱스 (Clustered Index)**
  - **특징:** 실제 데이터와 인덱스가 함께 저장됨 (데이터 자체가 인덱스 순서대로 물리적 정렬).
  - **개수:** 테이블당 **단 1개만** 생성 가능 (보통 Primary Key).
  - **성능:** 조회 속도가 매우 빠름.

1. **논클러스터드 / 세컨더리 인덱스 (Non-Clustered / Secondary Index)**
  - **특징:** 데이터 본문과 별도로 존재하는 인덱스 페이지 (데이터의 포인터/주소를 저장).
  - **개수:** 테이블당 **여러 개** 생성 가능.
  - **성능:** 인덱스를 거쳐 실제 데이터 페이지로 이동해야 하므로 클러스터드보다 약간 느림.

### 5. 인덱스 설계 및 사용 가이드라인

- **인덱스를 걸면 좋은 컬럼:**
  - 카디널리티(Cardinality)가 **높은** 컬럼 (중복도가 낮고 값이 명확히 구분되는 컬럼 ex. 주민등록번호, 이메일).
  - `WHERE`, `JOIN` 절에 자주 등장하는 컬럼.
  - 데이터 변경(`UPDATE`, `INSERT`)이 적고 조회가 압도적으로 많은 컬럼.

- **주의사항 (인덱스가 안 타는 경우):**
  - 인덱스 컬럼을 변형하는 경우: `WHERE YEAR(created_at) = 2026` ❌
  - `LIKE` 검색 시 앞쪽에 와일드카드를 쓰는 경우: `LIKE '%keyword'` ❌
  - 데이터 타입이 일치하지 않는 경우 (형변환 발생시) ❌
